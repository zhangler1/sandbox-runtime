# 无本地账户 AppContainer 沙箱验证记录

日期：2026-11-02。版本：0.3.0-preview。

执行环境：本机 Windows x64，OS build **26300.9711**，普通宿主令牌。该构建并非行内 Windows 10 VDI，不能写为“Windows 10 行内已通过”。构建使用系统 .NET Framework x64 C# 编译器，启用编译警告视为错误。

本轮验证入口：源码目录和交付包内的 `test/verify*.ps1`，均从普通宿主的 **Windows PowerShell 5.1** 调用。`verify.ps1`、`verify-direct-exec.ps1`、`verify-post-prepare-link.ps1`、`verify-overlap.ps1`、`verify-acl-shape.ps1`、`verify-residual-acl.ps1`、`verify-diagnostics.ps1` 已在本机合成 D 盘夹具中运行并返回成功；交付包内七份脚本也全部返回 0。

## 对旧原型结论的更正

旧 AppContainer/LPAC 原型的“外部普通文件可读取”结论不能用来否定机制：当时 outside 位于已获得递归 Package SID 读取授权的父目录下，继承了权限；部分原型还从 Codex 自带 AppContainer 中运行。此次使用普通宿主令牌，并让外部合成目录不继承工作区授权。

修正后的普通文件对照显示读取被拒。不过 AppContainer 的读取仍取决于真实 DACL：系统共享对象及显式向所有 AppContainer 授权的文件可以读。本版把这项边界写入手册并加入正向证明。
