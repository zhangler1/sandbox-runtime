# OpenCode V2 AppContainer 适配器验证记录

日期：2026-11-02 至 2026-11-03。适配器 `0.1.0-preview`，核心 CLI `0.3.0-preview`。测试环境：本机 Windows 10.0.26300.9711、Windows PowerShell 5.1、BocomCode V2 `2.1.4-bc.59bb7.n67`、模型 `zhipu/glm-5.2`。不是行内 Windows 10 VDI 验收。

## 已验证

| 检查 | 证据与结果 |
| --- | --- |
| 命令封装 | Node 测试验证命令只作为 Base64 数据进入宿主桥接；引号、中文与换行被原样传递，未知 shell/cwd/工具拒绝 |
| 真实桥接 | 宿主进程下执行 `test/bridge.test.mjs` 返回 0：工作区写成功、外部读写/嵌套 CMD 读失败；profile 未准备时退出 125，无宿主回退 |
| 启动前门槛 | `test/verify-launcher.ps1` 返回 0：插件 failed 不启动模型；单文件额外共享写授权被拒绝，文件哈希不变；参数、控制 cwd、环境隔离与临时配置回收通过 |
| 实际服务插件状态 | 使用本机 V2 `-CheckOnly`，查询实际 `/api/plugin` 为 active；随后模型请求才运行 |
| 模型普通 shell 自动接管 | `test/verify-opencode.ps1` 返回 0。提示词未包装 bank CLI；原始 `shell` 工具 exit=0，同时返回 READ-DENIED、WRITE-DENIED、完成标记；宿主确认工作区文件写成功、外部目标不存在、日志无合成秘密 |
| 非 shell 工具 | 模型实际调用 `read`，原始事件 status=error，错误为 `Bank sandbox: tool read is not permitted`；没有通过 shell 替代 |
| 项目配置边界 | 在可写工作区预置会写外部 sentinel 的恶意项目插件，两次模型请求后 sentinel 均不存在 |

真实模型日志在源码目录的 `test/verification/20261102-224802-394d3430-shell.jsonl` 与同前缀的 `non-shell.jsonl`，未放入交付包。测试结束已删除合成工作区、profile 与临时模型配置；未改常规 work 配置。

## 范围

这些结果覆盖受控 `launch.ps1` 单次调用路径。独立启动 OpenCode、任意 TUI、其他插件或直接连接其他服务器不在该结论内。Git for Windows/Git Bash 兼容、域名放行、强制遮蔽所有外部共享文件、行内 Windows 10/终端软件、以及 OpenCode 取消/崩溃场景的完整后代清理仍待验收。

启动器保留 AppContainer profile 以供工作区重复调用，业务结束后应执行 CLI `remove --workspace`。测试脚本则在 finally 中自动回收各自的合成 profile。
